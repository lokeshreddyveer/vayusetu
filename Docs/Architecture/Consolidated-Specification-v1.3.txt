01 Product vision and v1 cut line
VayuSetu is a privacy-first native iOS network utility unifying user-supplied VPN profiles, independent DNS configuration, Safari content blocking, selected DNS filter lists where technically enforceable, and on-demand diagnostics. It does not provide VPN servers, playlists, tracking, or a mandatory cloud account.
v1 committed
Conditional / post-v1
Five native tabs; native dark-first UI; custom coherent icons
macOS app (separate project)
Import/rename/switch supported VPN profiles; observable connection state
Local DNS-only interception without VPN interface (Phase 0 gated)
Supported encrypted DNS configuration and strict fallback policy
DoQ/DNSCrypt/DoH3 only with verified compatible implementation
Safari Content Blocker with user-selected lists
Safari Web Extension, element picker and cosmetic advanced workflows
Privacy Integrity Engine; four honest status tiles
Per-domain DNS statistics and Rule Inspector where queries are unobservable
Local event history, emergency reset, basic diagnostics
Advanced trusted Wi-Fi, censorship APIs, reputation lookups, privacy receipts
IP check and optional ASN; opt-in speed test only if ready
Google Safe Browsing integration, captive portal assistant, multihop
The v1 release does not depend on success of the local DNS-only filtering feasibility gate. Failure of that gate removes only that capability and its dependent DNS filtering features; independent encrypted DNS and Safari content blocking remain in scope.

06 Profiles and VPN user journeys
Only user-imported VPN profiles appear in the VPN list; DNS presets live in DNS, not Profiles.
Support import from Files and share sheet; QR for compatible formats. Validate format, endpoint, allowed IPs, secrets and duplicate identity before saving.
User-defined profile name separate from provider/server identity. Search and sort recent, alphabetical or last used.
Import while connected does not interrupt active session. Selecting another profile initiates one serialized switch operation; disclose possible brief disconnect.
Store private keys/passwords in Keychain; redact them in previews, logs, support exports and screenshots when possible.
Global Privacy Lock policy in Profiles → Connection Rules, with per-profile overrides only when explicitly defined.
Profiles can specify DNS policy; conflict resolver makes effective DNS source explicit.

Resolver catalog entries are optional presets, never provider endorsements. Custom IPv4/IPv6 and DoH/DoT endpoints include bootstrap, TLS hostname and certificate validation. DoQ, DNSCrypt and DoH3 require tested transport implementations and compatibility gates. Fallback levels: Strict encrypted (fail closed), encrypted alternatives, or plaintext/system compatibility only with informed opt-in. Never silently downgrade.
Benchmarking is on-demand and may reveal network metadata to resolver operators. Present latency, reliability, protocol support and last-tested timestamp, not a definitive privacy score.
08 Adblock and filtering UX
Suggested HaGeZi, OISD and StevenBlack lists are visible but unselected by default; the user must enable each one.
Support custom URLs/files, format validation, HTTPS fetching, ETag where supported, size caps, checksum or signature when supplied, atomic compilation and rollback.
Editor defaults user-created rules to Domain + subdomains, with an explicit Exact-only option. Every rule row shows its scope. Support syntax validation and nonsecret import/export.
Filtering paths are distinct: Safari declarative blocking, DNS inside a VPN tunnel, optional no-VPN DNS proxy, or upstream resolver filtering. Never combine their counters.
Advanced Rule Inspector and per-domain DNS counts are deferred unless a supported enforcement path exposes events. v1 includes a local Test Rule Match preview for user-defined and subscribed rules, with a clear explanation of the winning tier and scope; no fabricated live counts.
Temporary exceptions have scope labels: tunnel DNS may enforce expiry in extension; Safari requires rebuild/reload and cannot guarantee timely expiry while app is suspended.
Filtering does not remove all advertisements and DNS filtering does not cosmetically hide page elements.
09 Safari content blocker
Use Safari Content Blocker as the v1 declarative path. Compile supported rules into Safari-compatible JSON in the App Group, validate atomically, request reload using SFContentBlockerManager, then query enablement. Track three separate facts: OS enabled state, latest rule package/reload result, and rule effectiveness (not generally directly observable). Green tile label = Enabled when enablement and readiness are supported; it is not a guarantee of each individual block.
Safari Web Extension is a post-v1 separate capability for advanced cosmetic rules or user interactions if justified. Native extension use is allowed. Initial enablement may require the user to visit Apple-controlled Settings.

13 VPN engines and adapter contract
Use one VPNAdapter interface across Section 13 and Appendix B. It exposes prepare, connect, disconnect, collectCounters, capabilities and a statusStream. The application calls the adapter through ConnectionCoordinator, not directly from views. Native IKEv2 uses an adapter wrapper over OS VPN configuration; packet tunnels host WireGuard/OpenVPN where entitlements and libraries permit.
Connection state machine: idle → preparing → connecting → connected → disconnecting → idle; error and reconnecting branches are explicit. Serialize connect/switch/disconnect requests; protect against stale callbacks with operation IDs. Switching may briefly disconnect. Strict route policies must not promise traffic suppression beyond OS capabilities.
14 DNS execution architecture
Execution Path A: OS encrypted DNS settings without VPN interface. Path B: DNS within VPN packet tunnel with local query access where implemented. Path C: DNS proxy without VPN interface, conditional on Phase 0. Path D: user-selected upstream filtering resolver; VayuSetu cannot infer per-domain block counts without an upstream-supported and consented statistics interface.
A transport adapter must implement endpoint validation, reachability, authenticated negotiation, cancellation, timeout, bootstrap handling and strict fallback policy. Resolver metadata is not equivalent to actual enforcement. IPv6, split DNS, captive networks and network transitions require real-device tests.
15 Canonical filtering rule model
Rule grammar: new user-entered “example.com” defaults to Domain + subdomains, covering example.com and all subdomains. The editor offers Exact-only explicitly. Imported hosts-format entries match exact hostnames; supported ABP-style ||example.com^ matches the apex and subdomains. Normalize IDNA/punycode and lowercase hostnames; reject malformed wildcards and unsafe public-suffix scopes. Show “Exact” or “Domain + subdomains” on every row.
Resolution algorithm: (1) collect rules applicable to the enforcement surface; (2) evaluate the USER tier first, ahead of all subscribed-list matches; (3) within that tier, prefer exact-host over broader domain scope, then longest matching domain suffix; (4) for equally specific user rules, Allow wins over Block; (5) if no user rule matches, evaluate subscribed lists according to their native semantics, most-specific match, supported exception syntax and deterministic source/ID tie-breakers. Thus a user Allow example.com + subdomains overrides a subscribed Block ads.example.com; a user Exact Block ads.example.com overrides the broader user Allow. Never silently rewrite imported rule scope.
A non-overridable rule category is NOT assumed. If enterprise/OS safety restrictions exist, treat them as platform policy outside the user rule engine and disclose them. No vague “security-critical exception” is allowed.
16 Privacy Integrity Engine
Ingests adapter status streams, OS configuration evidence, Safari extension enablement, filter compiler/reload acknowledgments, DNS resolver observations and route checks. Reconcile at launch, foreground, network change, connect/switch, extension restart and stale timeout. Store timestamped local events without query history by default.
Integrity reports are evidence summaries, not an oracle. When two sources conflict, preserve provenance and show Needs attention or Limited with a reason. Do not let API-derived public IP tests override OS VPN connection state. Use no hidden background surveillance.

19 Session timing, Live Activities and metrics
For OS VPN configurations use NEVPNConnection.connectedDate when available and appropriate. For packet tunnel/independent DNS modes use authoritative transition timestamps with monotonic elapsed time during runtime and persisted wall-clock reconciliation across relaunch. Session resets on actual disconnect according to a documented policy. Format DD:HH:MM:SS with no artificial 99-day limit.
Live Activities can display sampled duration and traffic rates, but iOS controls update cadence. An activity generally ends after about eight hours and may remain visible on Lock Screen for a limited additional period. With no backend or push-to-start, VayuSetu does not automatically restart an expired activity in the background. A new activity is requested only after the user opens VayuSetu in the foreground and iOS permits it. The VPN continues independently.
Traffic rate = byte counter delta / elapsed monotonic interval. Reset baselines on reconnection/counter reset. Blocked statistics count actual enforcement events only; Safari content blocker does not expose reliable per-request blocked counters.
20 Reliability, recovery and privacy controls
Privacy Lock: evaluate includeAllNetworks and On Demand matching where supported, validate platform exclusions and display clear capability wording; never claim a universal kill switch. Emergency Reset is a mandatory v1 safety valve for potential connectivity lockout.
Strict encrypted DNS rejects silent plaintext fallback. Failure becomes Needs attention/Error and offers a consented policy change, not a hidden downgrade.
Emergency reset (v1): disable VayuSetu-managed active connections and DNS settings using available APIs, preserve profiles, show which OS-managed settings require manual steps.
Atomic config staging, last-known-good rollback, safe migration, bounded retry and exponential backoff. Safari filter-list health is v1: last update, compiled count, rejected rules, capacity failure and rollback outcome. Never silently truncate oversized lists.
Captive portal: rely on iOS login behavior; no in-app captive web browser in v1. Phase 0 must test strict routing (including includeAllNetworks) against captive login. Offer a clearly disclosed, user-confirmed temporary relaxation of applicable VayuSetu-managed Privacy Lock policy, with restoration guidance. Any connectivity probe is user-initiated or separately disclosed.
Trusted SSID automation: post-v1 pending network identity permissions, SSID/location eligibility, VPN On Demand rules and real-device behavior.
Local privacy event timeline: transitions and failures, no browsing content or query history by default.

22 Performance, accessibility and QA
Test native five-tab navigation on small and large iPhones, landscape where supported, Dynamic Type and VoiceOver.
Validate accessibility announcements: “DNS, Unknown” differs from “DNS, Inactive”; Safari green reads “Safari, Enabled”.
Measure launch responsiveness, profile import of large files, filter compilation throughput, memory peak, extension cold start, battery impact and reconnection times against baselined targets.
Use deterministic unit tests for rule specificity, IDNA, tie-breakers, snapshot staleness, time formatting, adapter state and config migration.
Real-device integration tests for Wi-Fi/cellular handoffs, IPv6, DNS strict fallback, permission denial, captive networks, VPN conflicts and extension reload failure.
Live Activity test at expiry boundary: activity ends, tunnel continues, no unsupported autonomous restart claim.
Security: logs and normal exports contain no secrets; only explicitly authorized encrypted backup may contain credentials.
Automated CI includes formatting, linting, static analysis, dependency/license audit, unit/UI tests and signed release validation.

Appendix B — Canonical Swift reference interfaces
The following illustrative interfaces are aligned with Sections 11–16. They are contracts, not drop-in production code.
enum ProtectionSubsystem: String, Codable { case vpn, dns, safari, adblock }
enum ObservedState: String, Codable {
  case inactive, enabledNotVerified, starting, active, limited,
       needsAttention, error, unknown
}
enum EvidenceSource: String, Codable {
  case osStatus, extensionAcknowledgement, routeObservation,
       resolverObservation, userPreference, unavailable
}
struct ProtectionSnapshot: Codable {
  let subsystem: ProtectionSubsystem
  let desiredEnabled: Bool?
  let observed: ObservedState
  let provenance: EvidenceSource
  let observedAt: Date?
  let stale: Bool
  let reason: String?
}
struct VPNCapabilities {
  let supportsCounters: Bool
  let supportsOnDemand: Bool
  let supportsStrictRouting: Bool
}
struct TrafficCounters { let bytesIn: UInt64; let bytesOut: UInt64 }
protocol VPNAdapter {
  var capabilities: VPNCapabilities { get }
  var statusStream: AsyncStream<ProtectionSnapshot> { get }
  func prepare(profileID: UUID) async throws
  func connect() async throws
  func disconnect() async throws
  func collectCounters() async throws -> TrafficCounters?
}
