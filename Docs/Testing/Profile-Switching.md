Reported behavior: tapping a target profile stopped the current VPN without establishing the target. Observed events showed a WireGuard connection request followed by timeout. No new extension startup breadcrumbs appeared. After rebuilding only app-owned WireGuard system registrations, a save attempt returned NEVPNErrorDomain:5 (configuration read/write failure) and rollback returned NEVPNErrorDomain:1 (invalid configuration). These codes identify failed configuration operations, not a proven server or credential problem.

Changes: reuse existing owned WireGuard managers when switching from IKEv2; preflight target WireGuard syntax, route support, encrypted resolver and requested native IPv6 policy before disconnect; handle selected/actual profile mismatch; route row/menu confirmation through the same serialized connection entry point. Added bounded secret-free setup and disconnect error codes. Registration repair is DEBUG-only, restricted to VayuSetu’s exact provider identifier, and preserves saved profile files and Keychain credentials.

Device result: following renewed system VPN permission, us-den/WireGuard reached established. Real-iPhone test passed, 1 test and 0 failures in ios/build/profile-switch-error-details.xcresult. Screenshot inspected. This establishes OS tunnel startup, not handshake, sustained traffic, DNS transport, or leak guarantees. User asked to disconnect VPN in Settings and leave phone unlocked for remaining validation.

## 12 October interaction audit

Native setup rejection was reproduced as NEVPNErrorDomain:1. Removing redundant writes to already stopped WireGuard adapters allowed a measured WireGuard → IKEv2 establishment. The reverse direction requested a WireGuard connection without new extension startup, then emitted NEVPNErrorDomain:5 and rollback error 1. The final source disables/read-backs the owned IKEv2 adapter before WireGuard startup, adds sanitized setup-phase error details, and retains all strict routing flags. VayuSetu's failed WireGuard system registration was rebuilt without deleting profile/Keychain data. Repeated final device validation is waiting for the phone to be unlocked; do not report both directions verified yet.


After the user unlocked the phone, both `profile-switch-final-20261012.xcresult` iterations failed at `start-native-tunnel` with NEVPNErrorDomain:1. The fresh-registration pair also failed. This confirms native startup rejection after policy read-back; it does not establish the underlying OS cause. The final build uses freshly loaded WireGuard managers, disables and verifies the previous adapter in both directions, and bounds invalid/stale activation recovery to two reloads with security-policy revalidation. Five new routing assertions pass (351 total regression checks). The final recovery hardware run (`profile-switch-bounded-20261012.xcresult`) was blocked at launch by iOS signing verification. Local strict/deep verification and in-place reinstall passed; app launch itself was denied by iOS. No successful final bidirectional test, no TestFlight upload, no security-verification claim.


After the user opened VayuSetu, `profile-switch-reopened-20261012.xcresult` passed a full WireGuard → IKEv2 → WireGuard sequence: 1 test, 0 failures, 54.948 seconds. Each state remained established for the test's five-second stability assertion. Screenshots show Fast/IKEv2 and us-den/WireGuard, both with protection verification pending. A repeat (`profile-switch-repeat-20261012.xcresult`) was blocked at app launch by developer signing verification while the VPN remained active; this is not a switching failure or a second pass. The test now supports two cycles in one app session through an explicit bounded test environment setting. Underlying OS signing rejection and initial configuration-invalid cause remain unconfirmed; no proof of traffic/leak security is inferred.


### Final two-cycle device result

User confirmed VPN off, app open and phone unlocked. `profile-switch-two-cycles-20261012.xcresult` passed **two complete WireGuard → IKEv2 → WireGuard cycles within one app launch**: 1 test, 0 failures, 104.560 seconds. The test checks protocol identity, OS tunnel-established state and five-second stability after each transition. The earlier single-cycle result also passed. Final observed adapter is us-den/WireGuard. Screenshots exported to `docs/verification-switch-two-cycles`; the earlier successful native and WireGuard screenshots were visually inspected. Temporary live-test opt-in was removed afterward.

This verifies the tested profile handoff on this Wi-Fi session. It does not prove long-duration stability, cellular transitions, IKEv2 traffic counters, exit identity, DNS filtering or leak isolation. Intermittent developer-build signing rejection on a separate app relaunch remains unresolved; starting the run with VPN off and app open allowed the in-session test to complete. Initial startup rejection was configuration-invalid after read-back; the exact OS cause and effect of each individual mitigation cannot be isolated from this evidence. The bounded activation reload branch did not need to fire in the successful single-cycle run and is independently covered only by its five unit assertions. No TestFlight upload was performed.
